## Method

Every run is a separate headless Claude Code session (no subagents), started in a
fresh `mktemp -d` directory outside this repository:

    PATH=<standalone claimlock copy>/bin:$PATH timeout 300 claude -p "<prompt>" \
      --safe-mode --output-format stream-json --verbose \
      --permission-mode acceptEdits --allowedTools <tools>

`tests/skills/run-scenario.sh` reproduces this for any variant, with fixtures from
`tests/skills/fixtures.sh`. The fix-round-1 reruns were made with those committed
scripts. The earlier runs used scratch copies of the same logic, and their prompt
files were checked byte-for-byte against the committed variants (see "Prompt
provenance").

- **Isolation: `--safe-mode`** ("all customizations (CLAUDE.md, skills, plugins,
  hooks, MCP servers …) disabled"; auth unaffected). Probe run, same flags, asked
  to list its skills and CLAUDE.md instructions. Verbatim answer:
  > 1. Skills: dataviz, update-config, keybindings-help, code-review, simplify,
  > fewer-permission-prompts, loop, schedule, claude-api, workflow-authoring, run,
  > init, security-review
  > 2. No. I don't have any CLAUDE.md or user/global memory instructions in my context.
  > 3. No. I don't see any hook-injected context.

  Only built-in skills; the user-level `evidence-standards` and `design-lenses`
  and the global CLAUDE.md are absent.
- **`stream-json` instead of `json`**: `json` returns only the final text; the
  stream records every tool call, which scenarios 2–4 are judged on.
- **Prompt before `--allowedTools`** (the flag is variadic).
- **Closed-book correction after round 1.** The R1 prompts told the session to
  `export PATH=<this repo>/bin:$PATH`. That leaked the repo path: the s4 session
  Globbed and Read this repo's plan and design spec, and s3 grepped
  `lib/claimlock/claims.py`. **R1 runs are contaminated, recorded, and excluded
  from the tally.** From R2 on, `bin/` and `lib/` were copied to a standalone
  `mktemp -d` directory placed on the session's PATH, and no prompt names any
  repository path.
- **GREEN** prepends the preamble given in `scenarios.md` and the skill's SKILL.md
  to the variant prompt. Each GREEN run uses the strongest RED variant for its
  scenario.

## REFACTOR

  - "`verify` is a write, never a read; use `show`/`check` to read". **This rule
    traces only to the contaminated, excluded s1-R1 run, and no GREEN run
    exercises it: it is untested.**
  - "Look at the diff yourself, every time", with red flags for "They reviewed it;
    I'll verify on their word" and "I was told to run verify and nothing else"

  - The rule against verifying on `kind: source` evidence alone, plus a note that
    `check` does not fail a valid unverified claim (s3-R2).
  - A hook section corrected to `docs/hook-semantics.md`: the end-of-turn warning
    reaches only the user.
- `operating-claimlock` gained "a red gate after import is the correct result",
  with red flags (s4-R3), and "do not invent a CI install source" (s4-R2).
- **Iteration 1 (green-s3):** `using-claimlock` shows the exact
  `evidence`/`sources` shape. Rerun green2-s3 wrote a valid, unverified claim —
  PASS.
- **Fix round 1 — accuracy** (checked against the code; no new rationalisations):
  - `using-claimlock`:
    - The `kind: source` rule is now stated as the author's rule. `verify`
      accepts source-only evidence, as s3-R2 showed.
    - A fresh hit also requires `claimlock show <id>` to print no `INVALID` line,
      because `search` flags only non-fresh claims.
    - `check` passes a *valid* unverified claim.
    - Hook descriptions follow the current `hooks.py`: the counts shown at session
      start, the HEAD-range report capped at 10 ids, and the end-of-turn report
      covering problems since the previous end of turn.
  - `operating-claimlock`:
    - Import keeps `status`, so only imported `verified` claims arrive unpinned
      and fail `check`.
    - The `check` summary line is described precisely (plain output; `--json`
      fields; exit 2 prints only an error).
    - Hook bounds are stated: 2,000 chars; 10 / 5 ids; the 5 s session lock;
      malformed-stdin notes in `hook-errors.log`.
  - `design-lenses`: a war story no longer asserts an unsourced ratio or count.
  - `evidence-standards`: "most runners" → "counted as a pass".
- **Not rerun after the accuracy edits:** GREEN s1 (`using-claimlock`) and
  GREEN s5 (`evidence-standards`) were **not** rerun after the fix-round-1
  accuracy edits above. The green-s1 and green-s5 PASS results were made
